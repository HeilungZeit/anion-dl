# anion-dl: CDNVideoHub как второй источник

> Рабочий план второго источника. **Чекбоксы — состояние работы:** агент,
> взявший задачу, отмечает сделанное прямо здесь и коммитит вместе с кодом.
> Решения и грабли по ходу переезжают в [AGENT.md](../AGENT.md), история
> этапов — в [PLAN.md](../PLAN.md).
>
> Статус: Э1 (загрузки), Э2 (онлайн-просмотр) и Э3 (предпочитаемый источник,
> пометка качества) сделаны. Проверены сборкой, тестами, живым резолвом с
> ремуксом через сайдкар и живым прогоном прокси (плейлист → сегмент MPEG-TS с
> CORS). В окне приложения не прогонялись — списки ручных проверок в конце.

## Контекст

У Kodik потолок — 720p. Shikimori на страницах `/animes/<id>/watch` встраивает
другой плеер, и в нём почти всегда есть 1080p. Задача — **дополнить** Kodik
этим источником, а не заменить: покрытие у него дырявое (см. ниже).

Прошлая попытка второго источника — Alloha — откачена (раздел «Alloha как
второй источник» в AGENT.md). Здесь не повторяется ни одна из её проблем, и
это проверено до начала работы, а не предположено.

## Что это за источник

«Плеер Шикимори» — это веб-компонент `<video-player>` CDNVideoHub
(`player.cdnvideohub.com`), внутри iframe. Видео лежит на CDN VK/OK
(`*.okcdn.ru`). Тайтл адресуется **MAL id** — у нас он есть в
`remoteIds.myanimelistId` (у Shikimori id совпадают с MAL, `shikimoriId` —
запасной).

Протокол — два GET, без авторизации, Referer и обфускации:

| Запрос | Ответ |
| --- | --- |
| `GET plapi.cdnvideohub.com/api/v1/player/sv/playlist?pub=3058&aggr=mali&id=<MAL>` | `items[]`: `vkId`, `voiceStudio`, `voiceType`, `season`, `episode` |
| `GET plapi.cdnvideohub.com/api/v1/player/sv/video/<vkId>` | `duration`, `hlsUrl` (мастер 144p…1080p), `mpeg{Tiny,Lowest,Low,Medium,High,FullHd,Qhd,2k,4k}Url` — прямые MP4 |

Остальное в ответе плейлиста (`ads`, `vast`) — реклама плеера, нам не нужна.

## Замеры (сентябрь 2026)

| | Kodik | Alloha (откачена) | CDNVideoHub |
| --- | --- | --- | --- |
| Потолок качества | 720p | 1080p | 1080p |
| Жизнь подписи | не замерялась, хватает на серию | ~2 мин | 24 ч |
| Резолв | GET + POST, 1,5–2 с | вебвью, UA-трюки, куски | 2 GET, ~0,5 с |
| Загрузка | ffmpeg HLS | покусочно + concat | ffmpeg HLS, как у Kodik |

- **Качество настоящее:** H.264 High 1920×1080 ~1,9 Мбит/с + AAC 256k,
  ~380 МБ на 24 минуты (ffprobe на живом файле).
- **1080p есть почти везде:** 16 из 18 случайных серий по 9 тайтлам.
- **Скорость:** ~13,5 МБ/с одним потоком на ещё не скачанных смещениях — серия
  1080p за полминуты.
- **Текущий конвейер подходит без изменений:** 1080p-вариант HLS — MPEG-TS с
  H.264+AAC. Наш LGPL-сайдкар с теми же флагами ремуксит его в 1920×1080.
- **Покрытие широкое, но с дырами.** У «Фрирен» 20 озвучек, у One Piece 1180
  серий, но у Attack on Titan, Death Note и ещё части тайтлов плейлист пуст
  (снято правообладателями). Отсюда «дополнить», а не «заменить».

## Грабли (каждая проверена запросом)

**Подпись привязана к классу User-Agent.** В URL есть `srcAg`: при резолве
Chrome-UA там `CHROME_MAC`, Safari — `WEBKIT`, curl — `UNKNOWN`. Ссылка,
выданная под один класс, на другом отвечает **400** — в том числе ffmpeg со
штатным `Lavf/…`. Резолв и потребитель обязаны идти с одним UA. Поэтому
резолв возвращает не строку, а `Stream { url, referer, userAgent }`, и
загрузчик ставит ровно то, что пришло.

**Подпись привязана к IP (`srcIp`).** Переключили VPN между резолвом и
загрузкой — отказ. Резолв и так идёт вплотную перед ffmpeg.

**CORS открыт только для `player.cdnvideohub.com`.** Любой другой `Origin`
получает 400 даже на MP4, `Access-Control-Allow-Origin` у HLS тоже только
свой. Поэтому онлайн-просмотр напрямую из вебвью невозможен (hls.js ходит
XHR'ом с Origin), а `<video>` без `crossOrigin` сделал бы кадр «чужим» —
апскейл Anime4K не смог бы его читать. Решение — прокси HLS (Э2).

**Первый вариант в мастере — 480p, порядок не по качеству.** Мастер нельзя
отдавать ffmpeg: `-map 0:v:0` взял бы 480p. Вариант выбирается по
`RESOLUTION` (`cvh::pick_variant`).

**`pub` обязателен** — без него 400. Подходит любой; `3058` — сам Shikimori.

**У фильмов нет `episode`** — считаем серией 1.

**Названия озвучек не совпадают с Kodik** (`AnilibriaTV` / `AniLibria` /
`AniLiberty`) и при этом иногда совпадают (`AniDUB`). Сливать по похожести
нельзя; см. «Идентичность дорожки».

**Таймингов опенинга нет.** Брать их у серии Kodik той же озвучки нельзя —
другой рип, другое смещение.

## Решения

**Локатор серии вместо URL плеера.** Поле `Video.iframeUrl` уже было ключом
серии везде: плеер, прогресс, задачи загрузок, маршрут окна. Серии
CDNVideoHub получают в нём `cvh:<vkId>`, Rust-команда `resolve_manifest`
разбирает локатор и зовёт `kodik` или `cvh`. Имя поля не менялось: оно
сохранено в `settings.json` и `watch-progress.json`. Версии API и хоста в
локаторе нет намеренно — сохранённые задачи переживут их смену.

**Идентичность дорожки — строка озвучки с меткой источника.** Строка озвучки
в приложении — ключ дорожки: по ней ищется прогресс, собирается адрес окна
плеера и имя файла. У CDNVideoHub она `«<студия> (CVH)»`
([video-source.ts](../src/app/api/video-source.ts)). Без метки «AniDUB» двух
источников смешался бы в один список серий и в один путь на диске. В списке
озвучек метка не видна: CDNVideoHub — своей группой, и её подпись говорит об
источнике.

**Плейлист запрашивает Rust** (`cvh_playlist`), а не `plugin-http`: домен
источника не попадает в capabilities, всё знание о нём — в
[cvh.rs](../src-tauri/src/cvh.rs). Отказ источника даёт пустой список и не
мешает Kodik (`CvhService` не падает).

**Бэк `anion-go` не трогаем.** Он проксирует `videos[]` из yani.tv; сайт этот
источник всё равно не проиграет из-за CORS, так что правка бэка ради одного
десктопа была бы костылём.

**Качество загрузок по умолчанию — 1080p как потолок.** Rust берёт лучшее не
выше. У Kodik это откат до 720p ценой одной проверки манифеста. В меню
вкладки загрузок 1080p виден только у дорожек CDNVideoHub.

**Апскейл остаётся для обоих источников.** 1080p-исходник кажется
самодостаточным, но Anime4K на нём по-прежнему полезен (большие экраны,
HiDPI, линии рисовки). Поэтому Э2 строится вокруг потока, который канва
может читать, а не вокруг «просто `<video src>`».

**Онлайн — прокси HLS через схему `stream`, а не прямой MP4.** План
предварительно называл MP4, но при разработке решение поменялось:

- hls.js кладёт сегменты в MediaSource, и кадр для канвы «свой» без всякого
  `crossOrigin`. CORS нужен только самим запросам hls.js — его даёт прокси.
- Ответ схемы Tauri — буфер целиком. Сегмент HLS (2–8 МБ) в него
  укладывается как есть; MP4 пришлось бы резать на Range-куски вручную.
- Весь механизм плеера — буфер на две минуты, переролв по 403, застой в
  конце серии, перемотка по отпусканию — остаётся прежним, без второй ветки
  подключения.

Прокси — [stream_proxy.rs](../src-tauri/src/stream_proxy.rs). Адрес
`stream://localhost/<токен>/<высота>p.m3u8` (Windows —
`http://stream.localhost/…`); подписанная ссылка в вебвью не попадает.
Сегменты в переписанном плейлисте относительные (`s/<base64 URI>`), hls.js
собирает их от адреса плейлиста — проверено его же резолвером URL для обеих
форм схемы. Отказ подписи у okcdn (400/403) прокси отдаёт как 403, чтобы
сработал переролв плеера; вытесненный токен — тоже 403.

**Плееру прокси выбирает Rust, а не UI.** `resolve_playback` отдаёт прямой URL,
если вебвью может взять поток сам (Kodik), и адрес прокси, если потоку нужны
заголовки, которых вебвью не пошлёт (`Stream::needs_proxy`). Плеер про
источники ничего не знает, кроме лестницы качеств.

**Качество просмотра общее для источников.** Сохранённые 1080p на Kodik
означают «лучшее, что есть» (`effectiveQuality`), а не пометку «1080p у
серии нет». Высоту потока через прокси плеер читает из имени плейлиста.

## Э3 — Выбор источника ✅

- [x] **Предпочитаемый источник без отдельной настройки.** Страницы
      настроек в приложении нет, а источник и так виден по группе озвучки.
      Поэтому запоминается источник озвучки, которую человек последней
      выбрал сам (`chooseDubbing`, ключ `source` в `player.json`).
      Автоматический выбор и «Смотреть» из загрузок предпочтение не меняют.
- [x] Порядок выбора озвучки — чистая функция `pickDubbing` с тестами: адрес
      → история тайтла → первая у предпочитаемого источника → первая вообще.
      Предпочтение решает только, с чего начать тайтл без истории. Если
      ответ может оказаться у CDNVideoHub, выбор ждёт его плейлист.
- [x] **Фактическое качество у загрузок.** `DownloadTask.quality`
      записывается после резолва (`Stream.height` у CVH, имя манифеста у
      Kodik) и показывается на странице загрузок и во вкладке «Загрузки»
      тайтла. В ленте серий вкладки «Просмотр» его нет: до резолва оно
      неизвестно, а резолвить весь сезон ради подписи — лишние запросы;
      играющее качество показывает меню плеера.

## Риски

- API неофициальный (`/v1/player/sv`), может смениться без предупреждения.
  Точка отказа одна — `cvh.rs`; проверка — `resolve_probe`.
- Тайтлы пропадают по жалобам правообладателей.
- Как и с Kodik, приложение идёт мимо рекламы плеера.
