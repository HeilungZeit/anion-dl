# anion-dl: авторизация, свой плеер, страницы фронта и «Продолжить просмотр»

> Рабочий план этапов Э9–Э15. **Чекбоксы — состояние работы, а не украшение:**
> агент, взявший задачу, отмечает сделанное прямо здесь и коммитит вместе с
> кодом, чтобы подхватить её мог любой следующий. Решения и грабли по ходу
> переезжают в [AGENT.md](../AGENT.md), история этапов — в [PLAN.md](../PLAN.md).
>
> Статус: Э9–Э15 сделаны.

## Контекст

`anion-dl` задумывался узким инструментом: каталог плюс скачивание серий в mp4.
Сейчас в нём четыре страницы (`/`, `/catalog`, `/anime/:id`, `/downloads`),
авторизации нет вовсе, а посмотреть серию можно только скачав её и открыв файл
в системном плеере.

Задача — довести десктопное приложение до уровня основного фронта `anion`: вход
в аккаунт, те же страницы и тот же визуальный язык, просмотр серий **внутри
приложения собственным плеером** (а не iframe Kodik, как на вебе), скачивание —
во вкладку на странице аниме. Плюс новая функция «Продолжить просмотр» по
принципу `anion-tv`: позиция и ряд остаются **полностью локальными**. Серверный
`/watch-progress` читается отдельно только для галочек и счётчика просмотренных
серий на странице тайтла. Последним шагом переписывается текстовка на самом сайте:
после этих изменений «качалка серий» перестаёт быть верным описанием.

## Решения, принятые с пользователем

| Вопрос | Решение |
| --- | --- |
| Плеер | `hls.js` + собственные контролы на Angular/Taiga |
| Авторизация | Вход и выход в приложении; регистрация, восстановление пароля, профиль — ссылки на `anion.online` в системном браузере |
| Прогресс просмотра | Два независимых потока: локальная позиция для продолжения; серверные номера просмотренных серий только читаются для страницы тайтла |
| Новые страницы | Закладки, Поиск, Расписание, Сезоны |
| Место плеера | Вкладка на странице аниме, как на фронте |
| Вкладки аниме | Описание (плеер + комментарии внизу вкладки), Загрузки, Похожие аниме. Манги нет |
| «Продолжить просмотр» | Ряд на главной |

### Допущения, которые стоит подтвердить или отклонить на ревью

1. **Отметки просмотренных серий на полосе серий остаются** — не как отдельная
   функция «продолжить», а потому что они есть в вёрстке фронта (`.watched`,
   значок `✓`). Источник — `GET /watch-progress/:animeId`; отметки общие для
   озвучек и не смешиваются с локальной позицией плеера.
2. **Плеер восстанавливает позицию при открытии серии.** Без этого ряд на
   главной некуда вести: карточка ряда открывает `/anime/:id?episode=N&dubbing=…`,
   и позиция должна подхватиться. Кнопки-героя «Продолжить серию N» из ТВ **нет**.
3. **Селект плеера не показываем.** На фронте он есть, но `anion-dl` умеет
   резолвить только Kodik; список из одного пункта — шум. Озвучка выбирается
   как на фронте.

## Ключевые технические находки

### 1. Прокси для потока не нужен — проверено живьём

**Замеры 17.09.2026** на серии `18599`, манифест
`cloud.solodcdn.com/useruploads/…:2026091809/720.mp4:hls:manifest.m3u8`:

| Что | Результат |
| --- | --- |
| Манифест без `Referer` | `200`, 10930 байт |
| Сегменты 1, 120 и 237 без `Referer` | `200`, полные тела |
| `Access-Control-Allow-Origin` на редиректе и на узле | `*` |
| `Range: bytes=0-1023` | `206` + `Content-Range` |
| Тип сегмента | `video/MP2T` |

Отсюда следует, что **плеер ходит за потоком обычным браузерным `fetch`**, и
ни Rust-прокси, ни схемы `anion-stream`, ни фичи `unsafe-headers` не нужно.
Ограничения `http:default` в capabilities на нативный `fetch` не
распространяются — они действуют только на `fetch` из `tauri-plugin-http`, а
`csp` в `tauri.conf.json` равен `null`.

Прежняя заметка «`Referer: https://kodikplayer.com/` обязателен и для
манифеста, и для каждого сегмента, иначе 403 на середине серии» перенесена из
`anion-tv` и **на этом CDN не воспроизводится**. Скорее всего она описывает
поведение прошлого узла или прошлой конфигурации; ffmpeg в загрузчике
`Referer` по-прежнему шлёт, и трогать это незачем — работает.

Что из плана уцелело: манифест оказался **медиаплейлистом**, а не мастером
(237 сегментов по 6 с, вариантов качества внутри нет). Значит переключение
качества — это повторный `resolve_manifest` с другим `preferredQuality`, а не
выбор уровня ABR, как и было заложено.

Что всё ещё верно: подпись в URL живёт до часа из `:YYYYMMDDHH/`, и на середине
длинной серии сегменты начинают отдавать 403. `SignatureClock` и
`ReResolveOnForbidden` нужны ровно для этого и остаются в объёме.

**Если CDN когда-нибудь закроется CORS-ом или потребует `Referer`**, запасной
план — прокси на своей URI-схеме в Rust; замеры и рассуждения лежат в истории
этого файла. Строить его заранее незачем: он стоит отдельного модуля, разбора
`Range`, переписывания плейлиста и регистрации схемы.

### 2. Сессия ездит сама, вручную её не подставить

`tauri-plugin-http` собран с фичей `cookies` по умолчанию: у плагина есть
персистентный cookie jar (файл `.cookies`). Бэк ставит `X-Session-ID` обычным
`Set-Cookie` на `anion.online`, поэтому после `POST /user/login` кука сама
поедет во все последующие запросы. Заголовок `Cookie` руками выставить нельзя
(см. выше) — это единственный рабочий путь.

`POST /user/login` возвращает `session` ещё и **в теле** (`dto.LoginResponse`),
но как транспорт он не нужен. Источник правды о входе — `GET /user`.

### 3. Что берётся из `anion-tv`

`anion-tv` — нативное Android-приложение на Kotlin (Media3/ExoPlayer), не JS.
Переносится не код, а логика:

| `anion-tv` | `anion-dl` |
| --- | --- |
| `SignatureClock` — срок подписи из `:YYYYMMDDHH/` в URL, упреждающий переролв за 5 минут | `src/app/player/signature-clock.ts` |
| `ReResolveOnForbidden` — ровно один тихий переролв на 403, затем ошибка | `src/app/player/re-resolve.ts` |
| `SkipController` / `Segment` — окно 90 с при неизвестной длине, хвост 120 с | `src/app/player/skip-controller.ts` |
| `ProgressPolicy.FINISHED_FRACTION = 0.90` | `src/app/api/watch-progress.service.ts` |
| Возобновление с любой позиции `> 0` — осознанное отличие после живой проверки | там же |
| Дебаунс записи 2 с + принудительный сброс при выходе | там же |
| `QualityLadder` | уже есть в `resolver.rs::upgrade_quality` |

### Э11 — страница аниме на вкладках

**Доработано после живого прогона** (замечания владельца проекта):

- **Нет автозапуска при открытии страницы.** Просмотр начинается только по
  нажатию; дальше признак `hasStarted` включает автозапуск при смене серии —
  это уже осознанное действие, и останавливаться там на постере незачем.
- **Контролы внутри кадра**, поверх видео, с затемнением снизу и скрытием
  через 2,5 с бездействия. Раньше они стояли панелью под плеером.
- **Полный экран делает окно Tauri, а не элемент.** `requestFullscreen()` в
  WKWebView отклоняется: Fullscreen API там за отдельной настройкой, которую
  Tauri не включает. Теперь окно уходит в полный экран через
  `getCurrentWindow().setFullscreen()`, а разметка растягивает плеер классом;
  подписка на `onResized` возвращает класс, если из режима вышли мимо нас.
  В capabilities добавлены `core:window:allow-set-fullscreen` и
  `allow-is-fullscreen`.
- **1080p убран из меню качества.** У Kodik его почти не бывает, и меню
  обещало то, чего нет. Лестница сведена в один модуль
  `player/manifest-quality.ts`: `DownloadService` теперь берёт её оттуда, а не
  держит свою копию.
- **Заставка — кадр из серии** (`randomScreenshots`), а не постер: постер
  вертикальный и в кадре 16:9 встал бы узкой полосой между чёрных полей.

**`@defer (on immediate)` вокруг плеера убран.** Он не откладывал ничего:
«Просмотр» — вкладка по умолчанию, а триггер `on immediate` срабатывает сразу.
hls.js и так лежит в ленивом чанке маршрута `anime` и грузится при открытии
страницы тайтла, а не при старте приложения. Размер бандла тут ни при чём —
владелец проекта отдельно сказал, что он его не заботит.

**Вкладка просмотра не размонтируется, а прячется классом.** `@switch`
уничтожал бы плеер вместе с позицией и буфером, и уход в загрузки за одним
кликом сбрасывал бы серию на начало. Побочный эффект: на скрытой вкладке
воспроизведение продолжается — звук идёт, пока вы смотрите загрузки.

**Описание из вкладки убрано, вкладка переименована в «Просмотр».** Текст уже
есть в шапке тайтла, второй такой же блок под плеером был дублем. С уходом
описания название «Описание» перестало отвечать содержимому.

### Э12 — «Продолжить просмотр»

- [x] **`src/app/api/watch-progress.service.ts`** (новый). Хранилище —
  `LazyStore('watch-progress.json')` из `@tauri-apps/plugin-store`, рядом с
  `settings.json`: разрешение `store:default` уже есть, IndexedDB не нужна.

  ```ts
  interface WatchRecord {
    animeId: number;
    title: string;
    poster: Poster;
    episode: number;
    dubbing: string;
    positionSecs: number;
    durationSecs: number;
    finished: boolean;   // липкий, как в anion-tv
    updatedAt: number;
  }
  ```

- [x] Правила один в один с `anion-tv`:
  - `finished` при `positionSecs / durationSecs >= 0.90`, обратно не снимается;
    `durationSecs` монотонно растёт, `positionSecs` зажимается длительностью;
  - `continueWatching()` — `!finished && positionSecs > 0`, сортировка по
    `updatedAt` убыв., **по одной свежей записи на аниме** (на ТВ это
    `distinctBy`; без него один тайтл занял бы весь ряд);
  - продолжение начинается с любой сохранённой позиции больше нуля; прежний
    порог в 30 секунд выглядел как потеря прогресса и убран после живой проверки;
  - досмотренная серия открывается с нуля, а не с сохранённой позиции;
  - запись: сигнал обновляется сразу, на диск — с дебаунсом 2 с плюс
    принудительный сброс в `ngOnDestroy` плеера и на `pause`.
- [x] **Отличие от ТВ:** там записи не чистятся вовсе. Здесь файл читается при
  старте, поэтому список обрезается до 500 записей, первыми выбывают самые
  старые `finished`.
- [x] **Ряд на главной** (`src/app/pages/feed/`) — секция «Продолжить смотреть»
  первой, до «Аниме сезона», скрыта при пустом списке. Карточка горизонтальная,
  с полоской позиции; ведёт на `/anime/:id?episode=N&dubbing=…`.
- [x] Страница аниме читает эти параметры через `withComponentInputBinding`,
  открывает вкладку «Описание» на нужной серии, плеер стартует с сохранённой
  позиции.

После живой проверки исправлено: события `0/0` до `loadedmetadata` больше не
стирают сохранённую позицию, ряд ограничен десятью свежими тайтлами. Смена
качества не запускает полный резолв Kodik повторно, а HTTP-тракт переиспользует
клиент и найденный endpoint между сериями.

Дополнительная защита: браузер присылает при демонтаже ещё и
`0/известная-длительность`. Любая нулевая позиция теперь игнорируется и не
обновляет `updatedAt`; незавершённая запись не удаляется из ряда после открытия.

Кнопка «Следующая серия» показывается строго в последние четыре минуты по
реальной длительности видео. `skips.ending` используется только как запасной
вариант, когда длительность ещё неизвестна: бэк иногда отдаёт этот тайминг
слишком рано для перехода на следующую серию.

- [x] Серверные галочки и счётчик на странице аниме читаются через отдельный
  `RemoteWatchProgressService` (`GET /watch-progress/:animeId`). Этот сервис не
  получает локальные тики плеера и ничего не пишет на сервер. Локальная позиция
  по-прежнему хранится по ключу «аниме + серия + озвучка» и служит только для
  ряда и возобновления воспроизведения. При обычном открытии тайтла в ленте
  заранее выбирается последняя просмотренная на сервере серия, доступная в
  текущей озвучке; URL из локального ряда и ручной выбор имеют приоритет.

## Проверка

1. **Сборка и типы.** `bun run build` — `strictTemplates` ловит большую часть
   ошибок вёрстки; `cd src-tauri && cargo test --lib` — существующие тесты плюс
   новые на разбор пути `anion-stream` и на переписывание плейлиста; на
   `SignatureClock` и политику прогресса — TS-тесты.
2. **Живой манифест без запуска окна.**
   ```bash
   cd src-tauri && cargo run --example resolve_probe -- "<URL плеера>" 720
   ```
   Полученный URL проверить `curl`-ом дважды — с `Referer: https://kodikplayer.com/`
   и без него: это подтверждает, что прокси вообще нужен и что схема его
   подставляет.
3. **Прокси отдельно от плеера.** После `bun run tauri dev` из devtools вебвью:
   `fetch('anion-stream://localhost/https/<хост>/<путь>.m3u8')` должен вернуть
   тело, начинающееся с `#EXTM3U`, и заголовок `Access-Control-Allow-Origin`.
   Затем запрос с `Range: bytes=0-1023` к любому сегменту — ожидается `206`.
4. **MSE.** В той же консоли `!!window.MediaSource && Hls.isSupported()` на
   каждой целевой платформе. Отрицательный ответ на Linux не блокирует этап —
   он включает нативную ветку.
5. **Авторизация.** Вход, перезапуск приложения, проверка что `GET /user`
   по-прежнему отвечает (значит cookie jar сохранился), затем выход.
6. **Прогресс.** Посмотреть 40 секунд серии, выйти со страницы, вернуться на
   главную — запись в ряду; открыть карточку — позиция восстановлена. Досмотреть
   до 90% — запись уходит из ряда. Файл `watch-progress.json` в каталоге
   конфигурации приложения читается глазами.
7. **Загрузки не сломаны.** Скачать серию из новой вкладки и убедиться, что
   очередь, прогресс, отмена и «Смотреть» работают как прежде.
8. **Фронт (Э15).** `ng build` в `../anion`; тексты вычитываются глазами.
9. **Визуальная приёмка — за пользователем.** По правилу AGENT.md окно для
   проверки UI сами не открываем; `bun run tauri build --bundles app` проверяет
   шаблоны, типы и доступность ассетов.
