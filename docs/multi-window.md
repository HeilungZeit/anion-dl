# anion-dl: серия в отдельном окне

> Рабочий план многооконности. **Чекбоксы — состояние работы, а не украшение:**
> агент, взявший задачу, отмечает сделанное прямо здесь и коммитит вместе с
> кодом, чтобы подхватить её мог любой следующий. Решения и грабли по ходу
> переезжают в [AGENT.md](../AGENT.md), история этапов — в [PLAN.md](../PLAN.md).
>
> Статус: Э1–Э5 и Э7 сделаны; в Э6 открыт один пункт — вход в функцию
> из списков серий. Всё проверено сборкой и тестами, живьём не прогонялось:
> список ручных проверок в конце документа ещё ждёт.

## Контекст

Сейчас приложение однооконное: плеер живёт внутри страницы тайтла (вкладка
«Описание») или на `/play/:taskId`, и любой переход по навигации его убивает.
Пока серия идёт, нельзя ни поискать следующий тайтл, ни поставить серию в
очередь, ни посмотреть расписание. В браузере это решается второй вкладкой,
но вкладки не знают друг о друге и не переживают закрытие окна; десктоп может
дать настоящее второе окно с общим состоянием.

Задача — открывать серию в собственном окне: без шапки приложения, со своим
полноэкранным режимом и своей геометрией, пока главное окно продолжает
работать. Это не PiP и не «оторванная вкладка»: в окне тот же `<ani-player>`
со скипами, выбором качества, апскейлом и переролвом подписи.

## Решения, принятые с пользователем

| Вопрос | Решение |
| --- | --- |
| Что выносится в окно | Только плеер: онлайн-серия и скачанный файл |
| Шапка в окне плеера | Нет; отдельный layout, а не `@if` внутри текущей шапки |
| Несколько окон плеера | Разрешены, максимум три; старт в одном ставит остальные на паузу |
| Закрытие окна плеера | Не выходит из приложения; позиция досохраняется перед закрытием |
| Закрытие главного окна | Как сейчас — выходит из приложения (трей отдельной задачей) |
| Повторное открытие той же серии | Поднимает существующее окно, а не создаёт второе |

## Главное архитектурное ограничение

**Каждое окно Tauri — отдельный вебвью, то есть отдельный экземпляр Angular.**
Корневые сервисы не общие: `WatchProgressService`, `DownloadService`,
`UserService` в окне плеера — другие объекты с другими сигналами, пишущие в те
же файлы стора. Всё, что ниже, следует из этого.

Из этого же следует, что́ переписывать **не надо**: очередь загрузок живёт в
Rust, а окна только слушают `PROGRESS_EVENT`
([download.service.ts:133](../src/app/api/download.service.ts:133)) — прогресс
сойдётся во всех окнах сам.

## Э1 — Капабилити и каркас окна

- [x] **`src-tauri/capabilities/default.json` — самое важное.** Сейчас там
      `"windows": ["main"]`, то есть новое окно с ярлыком `player-*` не получит
      **ни одного** разрешения: ни `store`, ни `event`, ни `http`, ни
      `core:window:allow-set-fullscreen`. Окно откроется, а плеер в нём молча
      не заработает. Добавить `"player-*"` в список окон (шаблон ярлыка
      поддерживается) либо завести вторую капабилити с урезанным набором:
      плееру не нужны `dialog`, `updater`, `process` и sidecar `shell`.
      Сделано второй капабилити
      [player.json](../src-tauri/capabilities/player.json) по шаблону
      `player-*`.
- [x] `core:webview:allow-create-webview-window` — в `core:default` его нет,
      добавить явно. **`core:window:default` оказался вообще read-only:**
      в нём нет ни `set-focus`, ни `unminimize`, ни `close`, ни `set-title` —
      все четыре добавлены явно, иначе окно создаётся, но поднять и закрыть
      его нечем.
- [x] `src/app/windows/player-window.service.ts` (новый) — создание окна:
      ярлык `player-<kind>-<id>`, размер 960×540, минимум 640×360,
      `title` из названия тайтла и номера серии. Если окно с таким ярлыком уже
      есть — `setFocus()` вместо создания.
- [x] Лимит в три окна плеера: при попытке открыть четвёртое — фокус на самое
      старое, без нового окна. Порядок открытия ведётся собственным журналом:
      порядок `getAllWebviewWindows` ничем не обещан. Каждый вебвью держит свой hls.js с буфером до
      200 МБ по конфигу ([video-player.component.ts](../src/app/player/video-player.component.ts)),
      и это единственная причина лимита.

## Э2 — Маршрут окна и layout без шапки

- [x] **Грабли продакшена.** В деве `devUrl` — это `ng serve`, и окно с адресом
      `/play/abc` откроется нормально: dev-сервер отдаёт `index.html` на любой
      путь. В собранном приложении ассеты отдаёт кастомный протокол по реальным
      путям файлов, `/play/abc` не существует, и окно откроется пустым. Работает
      в `tauri dev`, ломается в DMG — ровно тот класс ошибок, ради которых
      заведён раздел граблей в AGENT.md.
      Решение: окно открывается по `index.html?w=player&…`, параметры
      разбираются при старте и переводятся в навигацию роутера уже внутри
      вебвью. Hash-роутинг тоже закрыл бы вопрос, но затрагивает все ссылки.
      Разбор и сборка адреса — чистый модуль
      [window-target.ts](../src/app/windows/window-target.ts) с тестами.
- [x] `src/app/layouts/shell-layout.component.*` — нынешнее содержимое
      [app.component.html](../src/app/app.component.html) (шапка + `.content`).
- [x] **Окно открывает плеер, а не страницу.** Первая версия отрывала
      `/anime/:id?episode=…`, и в окне оказывался весь тайтл: описание,
      вкладки, комментарии. Заведён отдельный маршрут `window/player` и
      страница [window-player](../src/app/pages/window-player/window-player.component.ts),
      которая собирает серию из параметров: `?task=` для скачанной,
      `?anime=&episode=&dubbing=` для серии тайтла. Кадр занимает окно
      целиком — модификатор `.player--window` снимает пропорции 16:9, рамку и
      скругление.
- [x] `src/app/layouts/bare-layout.component.*` — только `<tui-root>` и
      `<router-outlet />`, без навигации и без отступов контейнера.
- [x] Разметку окна выбирает `AppComponent`: маршруты остались общими, а
      ветки layout'ов выбираются по параметру окна. Адрес переписывается
      `provideAppInitializer` **до** первой навигации роутера — иначе окно
      плеера сначала показало бы главную.
- [x] **`AppComponent` перестаёт быть местом для сервисов приложения.**
      Сейчас он инжектит `DownloadService`, `UserService`, `BookmarksService`,
      `RemoteWatchProgressService` и ставит значок на док
      ([app.component.ts:29](../src/app/app.component.ts:29)). Всё это должно
      остаться в shell-ветке: в окне плеера значок дока не нужен, а очередь
      трогать опасно (см. Э3).

## Э3 — Владелец очереди загрузок

- [x] **Двойной `drain()` — вторая по опасности вещь после капабилити.**
      `DownloadService.restore()` возвращает прерванные задачи в `queued` и
      сразу зовёт `drain()`, а защита от повторного запуска — поле `running`
      ([download.service.ts:128](../src/app/api/download.service.ts:128)),
      живущее в памяти одного вебвью. Второе окно с тем же сервисом поднимет
      второй ffmpeg на ту же задачу в тот же файл.
- [x] Очередью владеет только окно `main`: в окне плеера `DownloadService`
      либо не инжектится вовсе, либо поднимается в режиме «только чтение» —
      слушает `PROGRESS_EVENT` и не зовёт `drain()`.
- [x] Проверить, что `/play/:taskId` в отдельном окне обходится без записи в
      очередь: странице нужны `tasks()`, `missingFiles()` и `restored()`
      ([play.component.ts](../src/app/pages/play/play.component.ts)), но не
      запуск задач.

## Э4 — Синхронизация прогресса просмотра

- [x] **Гонка за файл.** `record()` меняет сигнал и через 2 секунды пишет в
      `watch-progress.json` **весь** снимок памяти
      ([watch-progress.service.ts](../src/app/api/watch-progress.service.ts)).
      Два окна — и окно, сохранившееся последним, затрёт чужие записи.
- [x] Чинится дёшево, потому что правила слияния уже вынесены в чистую
      `mergeWatchProgress(records, update)`: `record()` дополнительно шлёт
      Tauri-событие с одним `WatchProgressUpdate`, остальные окна ловят его и
      прогоняют через ту же функцию. Сигнатура функции менять не нужно —
      ровно тот случай, ради которого её выносили из сервиса.
- [x] Писать файл продолжает только то окно, где серия играет. Окно без
      воспроизведения обновляет память и ряд «Продолжить смотреть», но не
      дебаунсит запись.
- [x] Тесты на слияние из двух источников — рядом с существующими в
      `watch-progress.service.spec.ts`, без Tauri. Эхо собственного события
      отсекается по ярлыку окна в полезной нагрузке.

## Э5 — Закрытие окна и сохранение позиции

- [x] `onCloseRequested` в окне плеера: `preventDefault()`, `await flush()`,
      затем `destroy()` — именно `destroy`, потому что `close()` поднял бы это
      же событие снова. Сейчас `flush()` зовётся из `onDestroy`, а уничтожение
      вебвью системой не даёт промису шанса завершиться — теряются последние
      секунды просмотра.
- [x] Закрытие главного окна закрывает окна плееров; каждое перед этим
      досохраняет позицию.
- [ ] Проверить, что `emitPausedProgress()` при закрытии не присылает `0/0`:
      защита от нулевой позиции в `mergeWatchProgress` есть, но полагаться на
      неё как на единственную — значит потерять честную секунду.

## Э7 — Геометрия и мелочи

- [x] ~~`tauri-plugin-window-state`~~ — **отказались**: плагин хранит геометрию
      по ярлыку окна, а ярлык у нас функция от серии. Каждая новая серия
      получала бы пустую запись, а файл состояния копил бы по строке на каждую
      когда-либо открытую серию. Вместо него `PlayerBoundsService`: одна общая
      запись на все окна плеера в `windows.json`, плюс каскад в 32 px, чтобы
      второе окно не легло точно на первое. Геометрия **главного** окна
      по-прежнему не запоминается — это отдельная задача, и плагин там уместен.
- [x] Проверить полноэкранный режим в окне плеера: `getCurrentWindow()` и
      подписка на `onResized`

- [x] Значок на доке ставит только окно `main`: на macOS значок общий для

## Что проверить руками перед тем, как считать сделанным

1. Собранное приложение (не `tauri dev`): окно плеера открывается непустым.
2. Онлайн-серия в отдельном окне: скипы, выбор качества, апскейл, переролв
   подписи по 403.
3. Скачанная серия в отдельном окне: `allow_playback` выдаёт доступ
   asset-протоколу и из второго окна тоже.
4. Позиция: посмотреть минуту, закрыть окно крестиком, открыть снова — плеер
   продолжает с той же секунды.
5. Очередь: при открытом окне плеера запустить скачивание из главного окна —
   один ffmpeg, один файл, прогресс виден в обоих окнах.
6. Выход из приложения при открытых окнах плеера — без зависших процессов.
