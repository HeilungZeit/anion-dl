# anion-dl — план реализации

Десктопное приложение на Tauri v2: каталог аниме из бэка `anion-go` + скачивание
серий через плеер Kodik в mp4 для офлайн-просмотра.

Личный инструмент, не публичный продукт. Авторизации нет.

---

## 0. Ключевые вводные (проверено)

**Бэк уже отдаёт ссылку на плеер.** В `AnimeByIdResponseDTO` есть `videos[]`
([internal/dto/anime.go:218](../anion-go/internal/dto/anime.go)):

```go
type VideoDTO struct {
    VideoId   int           `json:"videoId"`
    Data      VideoDataDTO  `json:"data"`      // { player, dubbing }
    Number    string        `json:"number"`
    Date      int           `json:"date"`
    IframeUrl string        `json:"iframeUrl"` // ← готовый URL плеера
    Index     int           `json:"index"`
    Skips     VideoSkipsDTO `json:"skips"`     // { opening, ending }
}
```

Значит **скрейпить фронт anion.online не нужно вообще**. Берём `videos`,
отбираем нужный плеер, получаем прямой URL вида:

⚠️ `data.player` — это человекочитаемая подпись, а не идентификатор: реальные
значения `"Плеер Kodik"` и `"Плеер Alloha"`. Сравнение только по вхождению
подстроки, `=== "Kodik"` не сработает.

```
https://kodikplayer.com/season/120995/<hash>/720p?translations=false&only_episode=true&only_season=true&episode=1
```

**Что известно про сам Kodik** (из разбора его бандла):

- HLS через `hls.js`, **DRM нет** (ноль `widevine`/`clearkey`/EME).
- Страница плеера открывается **и без Referer** — 200. Это важно: hidden-webview
  может грузить её как top-level документ, а не как вложенный iframe.
- Ссылка на манифест приходит обфусцированной (base64 + посимвольный сдвиг),
  раскрывается на клиенте. Реверсить не будем — вебвью раскроет сам.
- ⚠️ CDN сегментов — **не** `video-lk-ok-ii.store`, как значилось в CSP на
  anion.online. При прямой загрузке страницы Kodik манифест приходит с
  `cloud.solodcdn.com`. Жёсткий фильтр по домену отсекал бы вообще всё.
- Качество зашито в путь URL (`/720p`), серия — в query (`episode=N`).

**Публичные эндпойнты `anion-go`** (auth только на `/user` и `/bookmarks`):

| Эндпойнт | Назначение |
|---|---|
| `GET /api/anime/feed` | главная: `seasonAnime`, `schedule`, `updates` |
| `GET /api/anime?<фильтры>` | каталог; фильтры в [url-params.go](../anion-go/internal/utils/url-params.go) — `sort`, `minRating`, `fromYear`, `toYear`, `epFrom`, `epTo`, `minAge`, `sortForward`, `requireFields` |
| `POST /api/anime/search` | поиск по строке |
| `GET /api/anime/:id` | детали + `videos[]` |
| `GET /api/anime/genres` | жанры для фильтров |

Осторожно: на `/api` висит `RateLimiterMiddleware` — при разработке легко словить
429 (я словил). Кэшировать ответы на клиенте обязательно.

## 1. Стек

**Rust / Tauri v2** — оболочка, hidden webview, скачивание, очередь.

**Фронт — Angular 22 без SSR + Taiga UI 5.** Не потому что «лучше React», а
потому что из `anion` переносятся готовые карточки, тема, пайпы и типы DTO.
Писать заново нечего. Отличия от основного проекта: SSR не нужен (нет
`isPlatformBrowser`-плясок), `AxiosService` не переносим — HTTP идёт через
`tauri-plugin-http`.

Плагины Tauri: `http` (обход CORS), `shell` (ffmpeg-сайдкар), `store`
(очередь и настройки), `dialog` (выбор папки), `opener` (показать файл в
Finder), `updater` (проверка и установка релизов), `process` (перезапуск после
обновления).

## 2. Архитектура

```
┌─ Angular UI ────────────────────────────────────┐
│ Feed · Catalog+Search · Anime · Downloads       │
└───────────┬─────────────────────┬───────────────┘
            │ tauri-plugin-http   │ invoke() + events
            ▼                     ▼
      anion-go /api        ┌─ Rust core ──────────┐
                           │ resolver (hidden wv) │
                           │ downloader (ffmpeg)  │
                           │ queue + store        │
                           └──────────────────────┘
```

Три Rust-модуля, всё остальное — UI.

### 2.1 Resolver — добыча m3u8

Самая нетривиальная часть. Алгоритм:

1. Rust создаёт `WebviewWindow` с `visible(false)`, грузит `iframeUrl` из
   бэка **напрямую** (top-level, без обёртки anion.online — проверено, что
   отдаётся 200 без Referer).
2. В вебвью инжектится `initialization_script`, который до загрузки страницы
   патчит `window.fetch`, `XMLHttpRequest.prototype.open` и сеттер
   `HTMLMediaElement.prototype.src`. Любой URL, содержащий `.m3u8`, уходит
   наружу.
3. Rust ловит URL, закрывает окно, отдаёт манифест в downloader.

Два подводных камня, оба решаемые:

- **IPC из удалённого origin.** Чтобы `window.__TAURI__` был доступен на
  `kodikplayer.com`, в capabilities нужно явно разрешить remote-домен
  (`"remote": { "urls": ["https://kodikplayer.com/*"] }`). Точный синтаксис
  сверить с доками своей версии Tauri v2 — он менялся.
  **План Б, если не заведётся:** скрипт пишет URL в `document.title`, Rust
  опрашивает заголовок раз в 200 мс. Некрасиво, но работает всегда и без
  расширенных прав.
- **Реклама.** Преролл — тоже HLS. Фильтруем по домену: контентный манифест
  идёт с `*.video-lk-ok-ii.store`, всё остальное игнорируем. Блокировать
  рекламу не нужно и опасно — плеер может ждать её завершения.

Таймаут на резолв — 60 с, потом ошибка «не удалось получить поток» с
возможностью ретрая.

### 2.2 Downloader — сборка mp4

Никакого своего HLS-качальщика. `ffmpeg` как sidecar-бинарь:

```
ffmpeg -headers "Referer: https://kodikplayer.com/" \
       -i <m3u8> -map 0:v:0 -map 0:a:0 \
       -c copy -bsf:a aac_adtstoasc \
       -progress pipe:1 -nostats \
       "<output>.mp4"
```

Почему так: поток не зашифрован и уже H.264+AAC, поэтому `-c copy` — чистый
ремукс, без перекодирования и потери качества, ~30 секунд на серию.
`aac_adtstoasc` обязателен при TS→MP4. Явный `-map` — чтобы при нескольких
аудиодорожках не утащило не ту.

Прогресс: парсим `-progress pipe:1` (`out_time_ms`, `total_size`), знаменатель
берём из длительности манифеста. Событие `download://progress` в UI раз в
секунду.

ffmpeg **бандлится в приложение** как sidecar — см. §2.4. Приложение не зависит
от того, что стоит на машине. Детали упаковки — §2.3.

Имя файла под телефон: `{romaji} - S{season}E{episode} [{dubbing}].mp4`,
недопустимые символы вычищаются.

### 2.3 Бандл ffmpeg (sidecar)

Кладём бинарь в репозиторий и подключаем через `externalBin` в
`tauri.conf.json`:

```json
{
  "bundle": {
    "externalBin": ["binaries/ffmpeg"]
  }
}
```

Tauri требует суффикс target triple в имени файла — на диске должно лежать
`src-tauri/binaries/ffmpeg-aarch64-apple-darwin`, а в конфиге путь пишется
**без** суффикса. Это самая частая причина «sidecar not found» на первой сборке.
Триплет своей машины: `rustc -vV | grep host`.

Вызов через `tauri-plugin-shell`, в capabilities нужно разрешение
`shell:allow-execute` с явным указанием sidecar-команды — иначе рантайм молча
откажет.

**Какой билд брать.** Нам нужен только ремукс: демуксер HLS/MPEG-TS, муксер MP4,
протоколы https/tls, битстрим-фильтр `aac_adtstoasc`. Энкодеры не нужны. Однако
при `--disable-everything` обязательны парсеры и декодеры `h264`/`aac`: они не
перекодируют поток, а дают `avformat_find_stream_info` извлечь размеры видео и
параметры аудио из MPEG-TS. Без декодеров MP4 падает с `dimensions not set`;
одних парсеров тоже недостаточно.

- Достаточно **LGPL-сборки** без `--enable-gpl` и без x264/x265. Это заметно
  чище юридически: GPL-сборка потянула бы за собой требования GPL на всё
  приложение при распространении. Для личного использования это неважно, но
  раздавать `.dmg` друзьям потом будет проще.
- Дефолтная статическая сборка (~80 МБ) избыточна. Фактическая минимальная
  сборка 8.1.2 с нужными demuxer/muxer/protocol/parser/decoder/bsf весит 2.4 МБ.

Готовые статические сборки под macOS есть у нескольких мейнтейнеров, но состав
и лицензия у них разные, а arm64 бывает не у всех — **перед тем как класть
бинарь в репо, проверьте `ffmpeg -version` на строку `configuration:`**: там
видно, включён ли `--enable-gpl` и есть ли лишние кодеки. Если подходящего
готового не найдётся, LGPL-сборка своими руками через `configure` — полчаса.

**Хранение.** Бинарь не хранится в git. `scripts/fetch-ffmpeg.sh` скачивает
официальный архив запиненной версии, проверяет SHA-256, собирает sidecar в
`binaries/`, а сама папка остаётся в `.gitignore`.

**Подпись на macOS.** Tauri подписывает приложение и sidecar ad-hoc identity
`"-"`; целостность `codesign --verify --deep --strict` проходит. Для
нотаризации эту identity нужно заменить сертификатом Developer ID Application:
Apple проверяет вложенные бинари, поэтому ffmpeg должен подписываться тем же
сертификатом, что и приложение.

### 2.4 Queue

Простая последовательная очередь (параллелизм 1, максимум 2 — CDN не любит
жадных). Состояние в `tauri-plugin-store` (JSON), чтобы очередь переживала
перезапуск.

Состояния задачи: `queued → resolving → downloading → done | failed | cancelled`.
Отмена = kill процесса ffmpeg + удаление частичного файла.

## 3. UI

Четыре экрана, минимализм — без комментариев, закладок, профиля.

**Главная (`/`)** — `GET /api/anime/feed`. Адаптивная сетка сезонного; карточка
ведёт на детали. Расписание и недавние обновления намеренно не показываются —
для десктопной качалки они создавали лишний информационный шум.

**Каталог + поиск (`/catalog`)** — единый экран. Строка поиска (debounce →
`POST /api/anime/search`), при пустом запросе — `GET /api/anime` с фильтрами
(жанр, год, рейтинг, сортировка) и бесконечным скроллом.

**Аниме (`/anime/:id`)** — `GET /api/anime/:id`. Постер, описание, метаданные.
Ниже — блок скачивания:

- селектор озвучки (уникальные `data.dubbing` среди `videos` с
  `data.player == "Kodik"`);
- селектор качества (`720p` / `480p` / `360p` — подменой сегмента пути в
  `iframeUrl`);
- список серий с чекбоксами, кнопки «Скачать выбранные» и «Скачать всё»;
- у уже скачанных — галочка и «показать в Finder».

**Загрузки (`/downloads`)** — очередь с прогрессом, отмена, ретрай, история,
кнопка выбора папки назначения.

**Визуальная синхронизация с `anion` — сделана.** Перенесены дизайн-токены,
стеклянная шапка, активные состояния навигации, постерные и горизонтальные
карточки, поверхности панелей, типографика, фокус и адаптивные брейкпоинты.
Каталог приведён к раскладке веб-фронта с жанровой навигацией и правой панелью
рабочих фильтров; нативные селекты заменены компонентами Taiga.
Новые функции веб-фронта (профиль, закладки, комментарии) намеренно не
переносились: десктоп остаётся инструментом каталога и скачивания.

## 4. Этапы

**Э0 — скелет. ✅ Сделано.** Скаффолд `create-tauri-app` подтянут до конвенций
`anion`: Angular 22 + zoneless + Taiga 5.9 (в шаблоне был Angular 20 с zone.js),
TypeScript 6.0, `less` для темы Taiga. Подключены плагины `http`, `shell`,
`store`, `dialog`, `opener` и выданы права в capabilities. Четыре ленивых
роута с заглушками, оболочка с навигацией.
Проверено: `ng build` и `cargo build` проходят чисто, ленивые чанки бьются
по страницам.

**Э1 — данные. ✅ Написано, в окне не проверено.** `AnimeService` поверх
`tauri-plugin-http` с дедупликацией запросов и кэшем, типы TS по Go-DTO,
карточка аниме, три экрана. Используется публичный бэк
(`https://anion.online/api`).
*Осталось проверить: каталог листается, детали открываются, список серий виден.*

**Э2 — resolver. ✅ Написано, вживую не проверено.** Rust-команда
`resolve_manifest` в [resolver.rs](src-tauri/src/resolver.rs): скрытое окно на
URL плеера, `initialization_script` патчит `fetch` и `XHR.open`, найденный
`.m3u8` с CDN-домена уходит наружу через `document.title`. Кнопка «Найти поток»
на странице аниме.

Канал — `document.title` вместо IPC: remote-IPC потребовал бы внести
`kodikplayer.com` в capabilities, то есть выдать чужой странице доступ к
командам приложения ради одной строки.

**Проверено вживую** через
[examples/resolve_probe.rs](src-tauri/examples/resolve_probe.rs) — пробник
поднимает тот же рантайм и гоняет резолвер из терминала, без кликов по окну.
Манифест приходит за ~1.4 с.

Четыре ошибки, вскрытые этой проверкой (все были в исходном плане):

1. **`window.title()` не отражает `document.title`** — отдаёт заголовок окна ОС.
   Опрос всегда видел исходный титул. Нужен push-колбэк
   `on_document_title_changed`.
2. **Плеер живёт во вложенном iframe.** Допущение «грузим top-level, хватит
   главного фрейма» неверно: в главном документе нет ни `<video>`, ни запросов.
   Нужен `initialization_script_for_all_frames`.
3. **Из фрейма нельзя писать заголовок верхнего документа** — фреймы шлют
   `postMessage` наверх, верхний пишет `document.title`.
4. **Кнопка запуска — `<a class="play_button">`.** Ни один селектор из
   первоначального списка по ней не попадал, и плеер просто не стартовал.

Диагностика оставлена в коде: при таймауте ошибка содержит состояние всех
фреймов (host, число запросов, наличие video, ошибки JS). Без неё отладка была
бы гаданием.

**Э3 — скачивание. 🟡 Обвязка готова, бинаря нет.**
[download.rs](src-tauri/src/download.rs) запускает сайдкар, разбирает
`-progress` и `Duration:` из stderr, шлёт события в UI. Кнопка «Скачать» и
выбор папки — на странице аниме, путь запоминается в `tauri-plugin-store`.
`externalBin` и `shell:allow-execute` со scope прописаны.

Подтвердилось предупреждение из §2.3: `tauri-build` проверяет `externalBin`
**на этапе компиляции**, и без файла падает даже `cargo build`.

Состояние на момент завершения Э3: прежняя версия
[scripts/fetch-ffmpeg.sh](scripts/fetch-ffmpeg.sh) копировала бинарь Homebrew.
Это было временное решение: сборка шла с `--enable-gpl` и динамически
линковалась с `/opt/homebrew` (416 КБ). Текущий скрипт заменён на исходную
LGPL-сборку в Э6.

**Проверено на собранном `.app`** (`tauri build --bundles app`): сайдкар внутри
бандла по-прежнему ссылается на `/opt/homebrew/Cellar/ffmpeg/8.1.2_1/lib/*.dylib`.
То есть цель «ffmpeg в бандле» формально **не достигнута** — приложение
работает только на машине, где ffmpeg установлен через Homebrew той же версии.
Для личного использования это ничего не меняет; для переноса на другую машину
нужна статическая LGPL-сборка.

Конвейер проверен на локальном HLS, отданном по HTTP (`exit=0`, на выходе
валидный mp4 h264+aac). Что выяснилось:

- `-headers` — приватная опция http-протокола. На локальном файле ffmpeg
  падает с «Option not found», поэтому тест обязан идти через http.
- `out_time_ms` вопреки имени содержит **микросекунды**: 12-секундное видео
  дало `out_time_ms=12023222`. Деление на 1e6 в `download.rs` верное.
- Формат строки `Duration: 00:00:12.00, start: …` совпадает с парсером.

**Связка проверена целиком на живом эпизоде:** резолвер отдал манифест,
ffmpeg собрал mp4 (`exit=0`, h264 + aac, `Duration: 00:23:40.12` — реальная
длина серии).

**Выбор качества — сделан.** Плеер стартует с 360p, поэтому пойманный манифест
всегда низкого качества. Качество зашито в имя (`…/360.mp4:hls:manifest.m3u8`),
и соседние лежат по тому же пути, поэтому `upgrade_quality` в
[resolver.rs](src-tauri/src/resolver.rs) подменяет число и проверяет
существование запросом. Проверено: запрос 720 → `/720.mp4:hls:`, запрос 480 →
`/480.mp4:hls:`, файл 1280×720. Селектор качества — на странице аниме, выбор
запоминается.

Лестница качеств — `[1080, 720, 480, 360]`, но **1080p у Kodik обычно нет**:
живая проверка дала 404 на 1080 и 240 при рабочих 720/480. Поэтому проверка
запросом обязательна, а не «подставили и поехали». Любая неудача — возврат
исходного URL: качество хуже ожидаемого лучше сорванной загрузки.

**Защита от рекламного манифеста — сделана** (Э5). Фильтр по домену не годится
(см. §0), поэтому опознаём контент по форме URL: `…/<качество>.mp4:hls:manifest.m3u8`.
Манифест такой формы принимается сразу; всё прочее придерживается как запасной
вариант и уходит в дело только через 8 секунд, если ничего лучше не пришло.
Так реклама не выигрывает гонку у серии, но и смена формата URL у Kodik не
оставляет приложение ни с чем.

**Две правки по итогам проверки файла:**

- `-movflags +faststart`. По умолчанию ffmpeg кладёт `moov` после `mdat`
  (проверено: `ftyp -> free -> mdat -> moov`), и плееры не начинают
  воспроизведение, пока не выкачают файл целиком. С флагом стало
  `ftyp -> moov -> free -> mdat`.
- **Ретраи + детекция потерь.** Вживую отвалился один из хостов CDN
  (`rock.cloud.solodcdn.com`), ffmpeg молча продолжил и вернул **exit=0**, а в
  файле не хватало 12 кадров из 600. Нулевой код возврата целостность не
  гарантирует. Добавлены `-reconnect*`.

  Детектор целостности переделывался **трижды**, и каждая версия была слишком
  строгой:

  1. Считал браком «Connection to tcp:// … failed». С ретраями обрыв штатно
     восстанавливается — прогон дал два обрыва при полных 600 кадрах из 600.
  2. Считал браком жалобы декодера (`non-existing PPS`, `no frame!`). HLS часто
     начинается не с ключевого кадра, и пара жалоб — норма. На реальной
     загрузке полная серия была помечена ошибкой.
  3. Допуск длительности в жёсткие 2 с. Последний блок `-progress` печатается
     до финального сброса буферов, поэтому итоговый `out_time` штатно на
     секунду-другую меньше `Duration`.

  Итог: **ошибка — только заметный недобор длительности** (допуск 1%, но не
  меньше 5 с). Жалобы декодера сверх порога дают предупреждение, файл при этом
  отдаётся. Дыру в середине не ловит ни одна проверка: при `-c copy`
  таймстемпы сохраняются и длительность остаётся полной. Это осознанный размен —
  гонять человека перекачивать 24 минуты из-за подозрения дороже, чем
  пропустить полсекунды.

Итоговый прогон: 600 кадров из 600, маркеров потери ноль, `moov` впереди.
H.264 High@4.1 yuv420p + AAC-LC 44.1 стерео — совместимость максимальная.

**Э4 — очередь. ✅ Написано, в окне не проверено.** Последовательный обработчик
в `DownloadService`, состояние в `tauri-plugin-store`, восстановление при
запуске. На странице аниме — чекбоксы, «Скачать выбранные» и «Скачать всё».
Экран загрузок: прогресс, отмена, повтор, «Показать» в Finder, очистка
завершённых.

Отмена сделана на стороне Rust (`cancel_download` + реестр `Downloads`): из JS
ручку дочернего процесса не достать, а брошенный ffmpeg продолжил бы качать в
фоне. Недокачанный файл удаляется — он всё равно непригоден.

Решения, которые стоит помнить:

- **Параллелизм = 1.** CDN уже показывал таймауты на одном потоке; несколько
  одновременных ffmpeg только повысят шанс потерять сегмент, а выигрыша нет —
  упирается всё в сеть.
- **Прогресс не сохраняется.** Прерванная выходом загрузка начинается заново:
  ffmpeg не умеет дописывать частичный mp4. При восстановлении активные задачи
  переводятся обратно в `queued`.
- **Резолв — внутри обработчика, а не при постановке в очередь.** Манифест,
  добытый впрок на весь сезон, к своей очереди протухнет.

**Э5 — полировка. ✅ Сделано.** Выбор качества и папки, имена файлов,
«показать в Finder», обработка «серия недоступна в Kodik», защита от рекламного
манифеста, собственная иконка и `.dmg`.

**Э6 — минимальная LGPL-сборка ffmpeg. ✅ Сделано.**

[scripts/fetch-ffmpeg.sh](scripts/fetch-ffmpeg.sh) собирает официальный FFmpeg
8.1.2 с запиненным SHA-256 и `--disable-everything`. GPL и x264/x265 нет;
HTTPS работает через Secure Transport на macOS, SChannel на Windows и OpenSSL
на Linux.

Минимальный состав: декодеры и парсеры `aac,h264`, демуксеры `hls,mpegts`,
муксер `mp4`, протоколы `file,http,https,tcp,tls,udp,pipe`, BSF
`aac_adtstoasc`. `pipe` нужен для `-progress pipe:1`. Декодеры понадобились
вопреки исходному плану: без них FFmpeg не извлекает параметры потоков из TS и
MP4 падает с `dimensions not set`.

`udp` нужен как скрытая link-time зависимость реализации OpenSSL TLS в FFmpeg
8.1.2: без него `tls_openssl.o` оставляет неопределённые `ff_udp_*`. На Windows
MinGW создаёт Makefile-цель `ffmpeg.exe`, поэтому скрипт не запрашивает там
Unix-цель `ffmpeg`.

Итоговый sidecar — 2.4 МБ. В собранном `.app` `otool -L` показывает только
`/usr/lib/libSystem` и Frameworks из `/System/Library`; ссылок на Homebrew нет.
Проверены HTTPS, локальный HLS целиком и 25 секунд живой серии Kodik (H.264 High
1280×720 + AAC-LC, 600 кадров, `moov` перенесён в начало).

**Упаковка macOS. ✅ Сделано.** Мастер-иконка
`src-tauri/icons/app-icon.png` преобразована Tauri CLI в PNG/ICNS/ICO и
проверена в 32/128/512 px. `bundle.macOS.signingIdentity` установлен в `"-"`:
Tauri ad-hoc подписывает приложение и ffmpeg с hardened runtime.

Финальный `anion-dl_0.1.0_aarch64.dmg` проходит `hdiutil verify`. После
монтирования проверены ссылка на `/Applications`, `codesign --verify --deep
--strict`, LGPL-конфигурация sidecar и отсутствие Homebrew-зависимостей.
Ad-hoc подпись не заменяет Developer ID и нотарификацию — они остаются
отдельным внешним шагом, если образ нужно распространять без предупреждений
Gatekeeper.

**Э7 — GitHub Releases для desktop-платформ. ✅ Настроено.**

`.github/workflows/release.yml` запускается на теге `app-v*`, проверяет его
совпадение с версией Tauri, нативно собирает LGPL sidecar и публикует DMG для
macOS ARM/Intel, NSIS EXE для Windows x64, AppImage и DEB для Linux x64.
У артефактов стабильные имена без версии, поэтому ссылки через
`releases/latest/download/...` не меняются. Подпись Windows и Developer ID для
macOS сознательно не настраиваются.

**Э8 — автоматические обновления. ✅ Настроено.**

Версия `0.1.2` подключает `tauri-plugin-updater` и проверяет при запуске
`releases/latest/download/latest.json`. Пользователь подтверждает установку в
нативном диалоге; после загрузки приложение перезапускается через
`tauri-plugin-process`. Ошибка проверки без сети не мешает запуску.

`createUpdaterArtifacts` включён, а release workflow публикует `.sig`,
платформенные update-пакеты и `latest.json`. Локально проверена реальная сборка
macOS: созданы `anion-dl.app.tar.gz` и `anion-dl.app.tar.gz.sig`.

Пара ключей создана локально в игнорируемой `.tauri/`. Публичный ключ встроен в
конфиг, приватный сохранён в GitHub Actions secret
`TAURI_SIGNING_PRIVATE_KEY`. Установленная `0.1.1` не может получить updater
сама, поэтому переход на `0.1.2` или новее будет последней обязательной ручной
переустановкой. В `0.1.3` macOS-матрица дополнена bundle `app`, чтобы вместе с
DMG публиковался подписанный `.app.tar.gz` и macOS попадал в `latest.json`.

## 5. Риски

| Риск | Митигация |
|---|---|
| Kodik меняет обфускацию ссылки | Не задевает нас — мы не декодируем, а слушаем сеть. Сломается только если сменят домен CDN → вынести фильтр домена в конфиг |
| Remote-IPC в Tauri v2 не настраивается | План Б через `document.title` |
| Преролл не даёт манифесту прийти | Ждём дольше, фильтруем по CDN-домену; рекламу не блокируем |
| 429 от `anion-go` | Клиентский кэш + дебаунс поиска |
| Не для всех серий есть Kodik | UI показывает только `videos` с нужным плеером; если пусто — честное «нет источника» |
| Ссылки на сегменты протухают | Резолвить манифест непосредственно перед стартом ffmpeg, а не заранее для всей очереди |
| Sidecar «не найден» на первой сборке | Почти всегда забытый суффикс триплета в имени файла или отсутствующее `shell:allow-execute` в capabilities |

## 6. Что сознательно не делаем

- Не реверсим `/ftor` и обфускацию — вебвью делает это бесплатно.
- Не пишем свой HLS-качальщик — ffmpeg уже умеет.
- Не встраиваем adblock — WKWebView не поддерживает расширения, а рекламный
  манифест отсекается фильтром по домену.
- Не добавляем Alloha на старте: у него Guard-верификация, капча и каскад
  фолбэк-манифестов. Если Kodik заработает — Alloha как запасной источник,
  отдельным этапом.
- Не тащим авторизацию и закладки — они требуют auth и не нужны для скачивания.
