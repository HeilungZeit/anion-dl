# anion-dl — справочник

Десктопное приложение на Tauri v2: каталог аниме из бэка `anion-go` + скачивание
серий через плеер Kodik в mp4 для офлайн-просмотра. Личный инструмент, не
публичный продукт. Авторизации нет.

Пошаговый план и история решений — [PLAN.md](PLAN.md). Здесь то, что нужно
знать, чтобы менять код и не наступить на уже пройденные грабли.

---

## Стек и конвенции

Angular 22 (zoneless, **без SSR**) + Taiga UI 5.9 + Tauri v2. Пакетный менеджер
— bun.

Конвенции унаследованы от [../anion/CLAUDE.md](../anion/CLAUDE.md) и действуют
здесь в полном объёме:

- `ChangeDetectionStrategy.OnPush` на каждом компоненте, состояние — только
  сигналы.
- Входы и выходы сигнальные: `input()`, `input.required()`, `output()`.
- DI только через `inject()` в поле класса.
- В шаблонах только встроенный control flow: `@if`, `@for` (с `track`),
  `@switch`, `@defer`.
- SCSS отдельным `styleUrl` рядом с компонентом.
- `strict`, `noUnusedLocals`, `noUnusedParameters`, `strictTemplates`. `any` не
  добавлять.
- Все страницы ленивые через `loadComponent`, у каждого роута есть `title`.

Отличия от основного проекта:

- **SSR нет** — плясок с `isPlatformBrowser` и `TransferState` не требуется.
- **`AxiosService` не переносим.** Весь ввод-вывод идёт через `fetch` из
  `@tauri-apps/plugin-http` (запрос уходит через Rust и не подчиняется CORS).
- **`@taiga-ui/legacy` не подключён** и подключать не нужно.
- Taiga запинен на 5.9.0 **везде**: `^5.9.0` для layout/styles резолвится в
  5.17 и даёт рассинхрон с core.
- Angular 22 требует TypeScript ровно 6.0.x; тема Taiga — `.less`, поэтому
  пакет `less` в devDependencies обязателен.
- Persistent cache Angular отключён в `angular.json`: связка Angular 22.1.2,
  `lmdb` 3.5.6 и Node 24.16 падает с double-free внутри нативного addon ещё до
  диагностики сборки. Без LMDB проект собирается примерно за три секунды.

## Как это устроено

```
┌─ Angular UI ────────────────────────────────────┐
│ Feed · Catalog+Search · Anime · Downloads       │
└───────────┬─────────────────────┬───────────────┘
            │ tauri-plugin-http   │ invoke() + events
            ▼                     ▼
      anion-go /api        ┌─ Rust ───────────────┐
                           │ resolver.rs          │
                           │ download.rs          │
                           └──────────────────────┘
```

Очередь живёт в TS (`DownloadService`), процессы ffmpeg — в Rust.

### Данные

Бэк `anion-go` отдаёт готовые ссылки на плееры, **скрейпить anion.online не
нужно**. Публичные эндпойнты (auth только на `/user` и `/bookmarks`):

| Эндпойнт | Отдаёт |
|---|---|
| `GET /api/anime/feed` | `seasonAnime`, `schedule`, `updates` |
| `GET /api/anime?<фильтры>` | список `Anime[]` |
| `POST /api/anime/search` | список `Anime[]`, строка в поле `search` |
| `GET /api/anime/:id` | детали + `videos[]` |
| `GET /api/anime/genres` | жанры |

В `videos[]` у каждой серии есть `iframeUrl` — прямой URL плеера, плюс
`data.player`, `data.dubbing` и `skips` с таймингами опенинга.

База API — `https://anion.online/proxy/api` (см. `src/app/api/api.config.ts`).
Именно `/proxy/api`, а не `/api`: на Vercel `/api/*` — каталог серверлес-функций
(там только SSR-рендер), запросы туда отдают 404. Разрешённые хосты перечислены
в `src-tauri/capabilities/default.json`; запрос на неразрешённый origin плагин
отклонит.

**Каждый запрос несёт заголовок `X-Anion-Client: anion-dl`.** Он нужен для
правила обхода в Vercel WAF: сайт стоит за Attack Challenge Mode, который отдаёт
JS-проверку под кодом **429**, а Rust-клиент выполнить её не может — до бэка
запрос вообще не доходит. Симптом обманчив: выглядит как рейт-лимит бэка,
поэтому смотреть надо на заголовок `x-vercel-mitigated` в ответе, а не на код.
Заголовок клиента секретом не является — приложение открытое, значение видно и в
исходниках, и в бинаре.

### Резолвер

Манифест не лежит в разметке: плеер получает его отдельным запросом, ссылка
приходит обфусцированной (base64 поверх посимвольного сдвига) и раскрывается в
JS. Трактов два, и порядок именно такой:

1. **HTTP** (`src-tauri/src/kodik.rs`) — GET страницы плеера, POST на `/ftor` с
   параметрами из её разметки, расшифровка ссылок. Полторы-две секунды.
2. **Вебвью** (`src-tauri/src/resolver.rs`) — страница выполняется в скрытом
   окне, а мы подслушиваем её сетевые запросы. Секунды в удачном случае, до
   двух минут при осечке.

Прежняя заметка «обфускация меняется с релизами, реверсить бессмысленно» была
**неверной** и стоила лишнего тракта: меняется не шифр, а адрес эндпойнта. Сдвиг
на 18 держится годами (той же схемой живёт `kodikwrapper`). Вебвью оставлен
фолбэком: смена эндпойнта или формы разметки делает загрузку медленной, а не
сорванной.

### Скачивание

Ремукс без перекодирования (`-c copy`): поток не зашифрован и уже в H.264 + AAC.
DRM у Kodik нет вовсе — ни Widevine, ни ClearKey, ни EME.

### Файлы на диске

Список задач и файлы — два разных источника правды, и они расходятся: файл
удаляют мимо приложения, а «Очистить завершённые» стирает задачу, оставляя файл.
Поэтому наличие файла спрашивается у файловой системы командой `probe_files`
(`src-tauri/src/files.rs`), пакетом на весь список.

Отсюда три следствия в UI: страница аниме помечает уже скачанные серии кнопкой
«Смотреть» вместо «Скачать», постановка в очередь один раз спрашивает про
перекачку готовых, а страница загрузок отличает «Готово» от «Файл удалён».

Раскладка по умолчанию — подпапка на аниме (`folderPerAnime` в `settings.json`).
Каталог создаёт Rust перед запуском ffmpeg: сам ffmpeg несуществующую папку не
заводит и падает уже после резолва манифеста, то есть впустую потратив вебвью.

## Грабли, на которые уже наступили

Каждый пункт стоил отладки. Прежде чем «упростить» — прочитать.

### Резолвер, HTTP-тракт

**`ref` берётся из `var ref`, а не из `urlParams`.** В `urlParams` то же
значение лежит percent-кодированным, подпись под него не подходит, и `/ftor`
отвечает `500` с телом `Error code: rs`. Это единственный симптом: параметры
приняты, но не сошлись. Диагностируется только по этому коду в HTML-заглушке,
поэтому он вытаскивается в текст ошибки.

**Параметр `info` слать нельзя.** Плеер добавляет его лишь при залогиненном
`userInfo`; с пустым `{}` эндпойнт отдаёт `404`, а не ошибку валидации.

**Ключ качества в ответе — не качество.** У живого Kodik под `links["720"]`
лежала ссылка с `480` в имени файла. Честный источник один — само имя манифеста,
и добор до желаемого по-прежнему делает `upgrade_quality` с проверкой запросом.

**Страница `/season/…` сама разворачивается в серию.** В её разметке уже
`vInfo.type = 'seria'` со своими `id` и `hash`, отличными от тех, что в адресе.
Поэтому парсить надо `vInfo`, а не URL, и оба формата ссылок обрабатываются
одним кодом.

**Эндпойнт вытаскивается из `app.player_single.*.js`.** Kodik его меняет
(`/ftor` → `/kor` → …), адрес спрятан в `atob("…")`. Скрипт весит 145 КБ,
поэтому качается только после отказа известного адреса. Рядом в том же файле
лежат ещё два `atob` — домен CDN и адрес статистики; отсеиваются по форме пути.

**Хост CDN — не обязательно `cloud.solodcdn.com`.** В ответах наблюдался
`sky.solodcdn.com`. Ещё одно подтверждение, что фильтровать по домену нельзя.

### Резолвер, вебвью-фолбэк

**`destroy()` не освобождает метку окна сразу.** Он лишь просит цикл событий
закрыть окно, и следующий `build()` с той же меткой падает с «a webview with
label `kodik-resolver` already exists». Из-за этого `RESOLVE_ATTEMPTS = 2` не
работал ни разу: вторая попытка отваливалась мгновенно, не дойдя до загрузки
страницы. Обнаружилось только когда фолбэк стали прогонять целиком — при живом
Kodik до повтора обычно не доходило. Лечится ожиданием освобождения метки перед
`build()`.

**`window.title()` не отражает `document.title`.** Возвращает заголовок окна ОС,
который Tauri с документом не связывает. Нужен push-колбэк
`on_document_title_changed`.

**Плеер живёт во вложенном iframe.** В главном документе нет ни `<video>`, ни
запросов за видео. Обязателен `initialization_script_for_all_frames`.

**Из фрейма нельзя писать заголовок верхнего документа.** Фреймы шлют
`postMessage` наверх, заголовок пишет только верхний фрейм.

**Состояния фреймов копить, а не перезаписывать.** Иначе в диагностику попадает
случайный последний фрейм (обычно статистика `ls.kodikres.com`), а плеерный не
виден.

**Кнопка запуска — `<a class="play_button">`.** Без клика по ней плеер не
запрашивает манифест вообще. Ни один «типовой» селектор плееров по ней не
попадает.

**Канал наружу — `document.title`, не IPC.** Remote-IPC потребовал бы внести
`kodikplayer.com` в capabilities, то есть выдать чужой странице доступ к
командам приложения ради одной строки.

**Фильтровать по домену CDN нельзя.** В CSP на anion.online значится
`video-lk-ok-ii.store`, но при прямой загрузке Kodik манифест приходит с
`cloud.solodcdn.com`. Контент опознаётся по форме URL:
`…/<качество>.mp4:hls:manifest.m3u8`.

**Качество зашито в имя манифеста.** Плеер стартует с 360p, поэтому пойманный
манифест всегда низкого качества; нужное добирается подменой числа. Существование
проверять запросом обязательно: 1080p и 240p отдают 404 при рабочих 720/480.

### Скачивание

**`out_time_ms` содержит МИКРОсекунды**, вопреки имени. Делить на 1e6.

**`-headers` — приватная опция http-протокола.** На локальном файле ffmpeg
падает с «Option not found», поэтому тестировать только через http.

**`exit=0` не означает целый файл.** При обрыве сегмента ffmpeg молча
продолжает и оставляет дыру.

**Ретраи здесь двухуровневые, и `-reconnect*` закрывают только нижний.** Они
работают ВНУТРИ одного запроса за сегмент: оборвалось соединение —
переподключиться. Когда запрос завершился отказом, решение принимает уже
HLS-демуксер, и его `seg_max_retry` по умолчанию `0` — что означает не «без
повторов», а «пропустить сегмент и идти дальше». Вот настоящий источник дыры при
`exit=0`. Замерено на этой сборке: с `seg_max_retry=0` мёртвый сегмент
открывается 1 раз, с `10` — 11.

Ценнее самих повторов побочный эффект: исчерпав их, ffmpeg завершается ненулевым
кодом, и тихая дыра превращается в явную ошибку.

**`-reconnect_on_network_error` покрывает только TCP/TLS.** Ответ 502/503
сетевой ошибкой не считается, и без `-reconnect_on_http_error` не
переспрашивается вовсе. В список входят `5xx,408,429`; **4xx добавлять нельзя** —
403 у CDN означает протухшую подпись, она не оживёт, и ретраи выльются в сотни
бесполезных запросов при стоящем прогрессе (ровно эти грабли и утопили Alloha).

**Без `-rw_timeout` зависший сокет висит вечно.** `reconnect_max_retries` по
умолчанию `-1` (бесконечно), а `reconnect_delay_total_max` ограничивает лишь
суммарную задержку МЕЖДУ попытками — случай «соединение живо, байты не идут» не
покрыт ничем. Значение в МИКРОсекундах, вопреки виду (тот же подвох, что у
`out_time_ms`).

**Keep-alive включать не надо, он уже есть.** У HLS-демуксера `http_persistent`
по умолчанию `true`, а `http_multiple` (`auto`) уже подтягивает следующий
сегмент параллельно текущему. `-multiple_requests` http-протокола (default
`false`) здесь ни при чём: сегментами занимается демуксер, а не протокол.
Ускорять загрузку опциями ffmpeg нечем — остаётся только параллелизм очереди.

**CDN разводит запросы по краевым узлам, и мерить его тяжело.** `cloud.solodcdn.com`
отвечает `302` на узел вида `storm.…` / `rock.…`, а здоровье у узлов разное:
отдельные уходят в TCP-таймаут на минуту-другую и возвращаются сами. Отсюда две
ловушки для любого замера скорости:

- **Прогрев.** Повторный проход по тому же отрезку идёт из кэша и врёт в разы —
  наблюдалось 5,7× между первым прогоном и повтором. Каждая точка замера обязана
  брать ещё не скачанное смещение.
- **Лотерея узла.** Разброс между одинаковыми прогонами достигает 1,8× — столько
  же, сколько разница между 1 и 3 потоками. Не зафиксировав узел, эффект
  меньше двукратного из шума не вытащить.

Проверять код ответа на `200` при этом бессмысленно: штатный ответ здесь `302`,
и проверка «жив ли CDN» по коду 200 даёт ложный отрицательный результат.

**Tauri отдаёт stderr уже построчно**, срезая перевод строки (`CommandEvent`:
«bytes until a newline or carriage return is found»). Склейка хвоста через
`join("")` давала пользователю одну нечитаемую стену — нужен `join("\n")`.

**Детектор целостности трижды был слишком строгим.** Итоговое правило: **ошибка
— только заметный недобор длительности** (допуск 1%, но не меньше 5 с). Не
считать браком:

- «Connection to tcp:// … failed» — с ретраями штатно восстанавливается;
- жалобы декодера (`non-existing PPS`, `no frame!`) — HLS часто стартует не с
  ключевого кадра, пара жалоб норма; сверх порога это предупреждение, не отказ;
- недобор в секунду-другую — последний блок `-progress` печатается до
  финального сброса буферов.

Дыру в середине не ловит ни одна проверка: при `-c copy` таймстемпы сохраняются
и длительность остаётся полной. Осознанный размен — гонять человека
перекачивать 24 минуты из-за подозрения дороже, чем пропустить полсекунды.

**`-movflags +faststart` обязателен.** По умолчанию `moov` пишется после `mdat`,
и плееры (в том числе телеграмный) не начинают воспроизведение, пока не
скачают файл целиком.

**Явные `-map 0:v:0 -map 0:a:0`** — иначе при нескольких аудиодорожках ffmpeg
может взять не ту озвучку. **`-bsf:a aac_adtstoasc`** обязателен при TS → MP4.

### Сайдкар и сборка

**`tauri-build` проверяет `externalBin` на этапе компиляции** — без файла падает
даже `cargo build`.

**Имя файла обязано нести target triple**: на диске
`binaries/ffmpeg-aarch64-apple-darwin`, в `tauri.conf.json` — путь **без**
суффикса. Причина №1 ошибки «sidecar not found». Второй частый случай —
отсутствующее `shell:allow-execute` со scope.

**При `--disable-everything` нужны декодеры и парсеры `h264`/`aac`.** Сам
ремукс по-прежнему идёт через `-c copy`, но без зарегистрированных декодеров
`avformat_find_stream_info` не извлекает из MPEG-TS размеры видео и параметры
аудио. MP4-мультиплексор падает с `dimensions not set`. Это проверено отдельно:
одних парсеров недостаточно.

**`opener:default` не покрывает раскрытие пути** — для «Показать в Finder»
нужен `opener:allow-reveal-item-in-dir`.

### UI

**Визуальный язык синхронизирован с основным фронтом `anion`.** Цвета,
поверхности, радиусы, отступы, состояния фокуса и акцентные градиенты заведены
как `--anion-*` в `src/styles.scss`. Шапка повторяет композицию веб-фронта:
стеклянный фон, wordmark, компактные активные пункты и отдельный вход в поиск.
Карточка `AnimeCardComponent` имеет два варианта: постерный для главной и
горизонтальный `wide` для каталога. Бизнес-специфичные экраны скачивания
используют те же токены, а не стандартный вид Taiga.

Каталог повторяет раскладку основного фронта: раскрываемая навигация по жанрам,
сетка горизонтальных карточек и липкая панель фильтров справа. Название, жанры,
тип, статус, диапазон лет и сортировка реально передаются в `AnimeQuery`;
массивы по-прежнему сериализуются одной строкой через запятую. Селекты в
фильтрах и на странице аниме собраны через `TuiSelect` внутри `tui-textfield` —
нативные `<select>` сюда не возвращать.

**Поиск не гасит выдачу на каждое нажатие.** Дебаунс в 400 мс был всегда, но
список показывал лоадер по `isSearching()` сразу, а `resource` вдобавок обнуляет
`value()` при смене params — вместе это выглядело как «дебаунса нет». Прошлая
страница удерживается в `linkedSignal` и на время запроса просто гаснет.

Каталог и поиск используют серверную пагинацию по 20 элементов. Бэк не отдаёт
`total`, поэтому запрос берёт 21 элемент: первые 20 показываются, 21-й служит
точным признаком наличия следующей страницы. При поиске и изменении фильтров
страница сбрасывается на первую. Начальная сортировка — `top`
(`Релевантности`), как на основном фронте.

**Сверка с диском не подписывается на `tasks()`.** Этот сигнал дёргается раз в
секунду от событий прогресса, и подписка на него означала бы вызов
`probe_files` на каждый тик. Эффект на странице аниме смотрит на
`pending().length`: он меняется только на переходах статуса — ровно тогда, когда
файл мог появиться.

**Имя папки чистится той же `sanitize`, что и имя файла.** Иначе название с
двоеточием («Название: Подзаголовок» — таких много) дало бы лишнюю вложенность
на macOS и вовсе несоздаваемый каталог на Windows. Точка в начале там же
срезается: она делает папку скрытой, и пользователь не нашёл бы свои серии.

**`opener:default` не включает `allow-open-path`** — для кнопки «Открыть» нужно
разрешение отдельно. Само `reveal` в дефолтный набор как раз входит, хотя
явная строка в capabilities осталась.

**Кнопка серии не перезапускает уже скачанное.** У серии, файл которой лежит на
диске, стоит «Смотреть» — она открывает файл в системном плеере, а рядом стрелка
на `/downloads?task=<videoId>`: страница загрузок подсвечивает эту задачу и
подкручивает к ней список. Раньше подпись «Готово» выглядела итогом, а клик
молча начинал скачивание заново. Отменённая серия подписана действием
(«Повторить»), а не состоянием. Названия в списке загрузок ведут на страницу
аниме; у задач, сохранённых до появления `animeId`, он равен нулю — там ссылки
нет, поэтому ветка с обычным `<strong>` нужна.

**`DownloadService` инжектится в `AppComponent`** ради счётчика активных
загрузок в шапке. Побочный эффект намеренный: очередь восстанавливается при
старте приложения, а не при первом заходе на страницу загрузок.

**Полоса «В очереди» на странице аниме считается от очереди, а не от клика.**
Так она переживает перезаход на страницу и не врёт после «Скачать все серии».
Учитываются только серии этого аниме — сравнение по `videoId`.

**Подпись «показать файл» зависит от ОС** и берётся из user agent вебвью
(`Macintosh` → Finder, `Windows` → проводник, иначе — «Показать в папке»).
`plugin-os` ради одной строки не подключается: это Rust-зависимость плюс запись
в capabilities.

**Не передавать обычный stringify-колбэк в `itemContent` у
`tui-data-list-wrapper`.** `itemContent` — PolymorpheusContent: функция получает
контекст `{$implicit: item}`, а не сам item. Для чисел это дало
`[object Object]p`, для объектных опций — пустые строки. Достаточно задать
`[stringify]` на родительском `tui-textfield`: wrapper унаследует его через
items handlers. У одиночного поискового поля cleaner отключён намеренно: он
зовёт `setValue(null)`, а `draft` — строка.

**Директивы `input[tuiTextfield]` в Taiga 5 нет.** Обычный текстовый инпут
внутри `tui-textfield` помечается `tuiInput` (`TuiInputDirective`); у
`tuiSelect` она подключена через `hostDirectives: [TuiWithInput]`, поэтому
селекты выглядели правильно, а поиск — нет. Атрибут `tuiTextfield` на инпуте
молча ничего не делал: `strictTemplates` неизвестные атрибуты не ловит, ошибки
не было. Без `tuiInput` инпут не получает от Taiga ни абсолютного
позиционирования, ни отступов и рисуется обычным флекс-ребёнком — со своей
рамкой и фоном поверх поля.

Отсюда же тянулась целая пачка обходных правил в `.filter-control`
(фиксированная высота, `overflow: hidden`, `flex-wrap: nowrap`, сброс инпута
через `!important`) — все они лечили симптомы и удалены вместе с причиной.

Иконка шапки не дублируется в `src/assets`: Angular копирует master-файл
`src-tauri/icons/app-icon.png` в `assets/app-icon.png` через `angular.json`.

**Окно самостоятельно не открывать для проверки UI** — это унаследованное
правило `../anion/CLAUDE.md`. Production-сборка и упаковка `.app` проверяют
шаблоны, типы и доступность ассетов, визуальную приёмку проводит пользователь.

**Цепочка высот до скролл-контейнера должна быть определённой.** Между `body` и
`tui-root` стоит `app-root` с `display: block` без высоты — именно там она
рвалась. `body` — флекс-контейнер, `app-root` — `display: flex; flex: 1`.

**`overflow: hidden` на скроллере глушит колесо, но не `scrollTop`.** Кастомный
скроллбар Taiga (`tui-scroll-controls`) двигает контейнер программно, поэтому
симптом выглядит как «ползунок тащится, колесо мертво».

**`data.player` — подпись, а не идентификатор.** Реальные значения «Плеер
Kodik», «Плеер Alloha». Сравнение только по вхождению подстроки.

**Массивы в query бэк режет по запятой** (`strings.Split(val, ",")`).
Повторяющиеся ключи он не увидит — `c.Query` вернёт только первый.

**На `/api` висит рейт-лимитер.** Без клиентского кэша обычная навигация
упирается в 429.

### Автообновление

Начиная с `0.1.2` приложение проверяет обновления при запуске через
`tauri-plugin-updater`. Манифест берётся из публичного GitHub Release:
`https://github.com/HeilungZeit/anion-dl/releases/latest/download/latest.json`.
Проверка без сети завершается молча; при наличии новой версии показывается
нативный диалог, после подтверждения пакет устанавливается и приложение
перезапускается.

Подпись updater-артефактов — не Developer ID и не Windows code signing. Это
отдельная обязательная проверка целостности Tauri, отключить её нельзя. Публичный
ключ встроен в `tauri.conf.json`, приватный лежит локально в
`.tauri/anion-dl.key`; вся `.tauri/` исключена из Git. Ключ нужно отдельно
сохранить в надёжном месте: при его потере уже установленные копии не смогут
принять обновления, подписанные новым ключом.

Для CI содержимое приватного ключа должно быть записано в GitHub Actions secret
`TAURI_SIGNING_PRIVATE_KEY`. Ключ создан без пароля, поэтому
`TAURI_SIGNING_PRIVATE_KEY_PASSWORD` в workflow явно пустой. `tauri-action`
публикует update-артефакты, `.sig` и объединённый `latest.json`.

Updater на Linux использует AppImage. Пользователи `.deb` обновляются вручную
или через будущий apt-репозиторий. Версия `0.1.1` ещё не содержит updater:
переход на `0.1.2` для неё также ручной, все следующие обновления — уже
автоматические.

## Решения, которые выглядят странно, но осознанны

**Параллелизм загрузок = 1.** CDN показывал таймауты и на одном потоке;
несколько одновременных ffmpeg только повысят шанс потерять сегмент, а выигрыша
нет — упирается всё в сеть.

**Прогресс не сохраняется между запусками.** ffmpeg не умеет дописывать
частичный mp4, прерванная загрузка честно начинается заново.

**Вебвью-тракт не удалён, хотя обычно не выполняется.** Он покрывает ровно то,
на чём HTTP-тракт хрупок: смену эндпойнта, формы разметки или шифра. Пока
фолбэк не сработал ни разу в реальной эксплуатации, удалять его рано — цена
хранения нулевая, цена ошибки — неработающее приложение до следующего релиза.

**Резолв — внутри обработчика очереди, а не при постановке.** Подписи в URL
сегментов протухают; манифест, добытый впрок на весь сезон, к своей очереди
будет мёртв.

**Отмена живёт в Rust.** Из JS ручку дочернего процесса не достать, брошенный
ffmpeg продолжил бы качать в фоне.

**Диагностика резолвера оставлена в коде.** При таймауте ошибка содержит
состояние всех фреймов. Без неё отладка была гаданием — это проверено.

## Команды

```bash
bun run tauri dev
```

```bash
bun run tauri build --bundles app
```

Собрать установочный DMG:

```bash
bun run tauri build --bundles dmg
```

Прогнать резолвер из терминала, без кликов по окну:

```bash
cd src-tauri && cargo run --example resolve_probe -- "<URL плеера>" 720
```

```bash
cd src-tauri && cargo test --lib
```

Собрать запиненный LGPL ffmpeg из официальных исходников для текущей платформы
(имя с триплетом делает сам скрипт):

```bash
./scripts/fetch-ffmpeg.sh
```

Первым аргументом можно передать target triple. Для сборки без скачивания путь
к архиву `ffmpeg-8.1.2.tar.xz` передаётся вторым аргументом:

```bash
./scripts/fetch-ffmpeg.sh x86_64-unknown-linux-gnu /path/to/ffmpeg-8.1.2.tar.xz
```

Публикация релиза запускается только версионным тегом, совпадающим с версией в
`src-tauri/tauri.conf.json`:

```bash
git tag app-v0.1.3
git push origin app-v0.1.3
```

Workflow `.github/workflows/release.yml` создаёт публичный GitHub Release и
загружает DMG для macOS ARM/Intel, NSIS EXE для Windows x64, AppImage и DEB для
Linux x64, а также подписанные updater-артефакты и `latest.json`. Подпись ОС и
нотарификация намеренно не настроены.

Перед первым updater-релизом один раз добавить локальный ключ в GitHub Secrets:

```bash
gh auth login
gh secret set TAURI_SIGNING_PRIVATE_KEY < .tauri/anion-dl.key
```

Локальная production-упаковка с updater-артефактом также требует ключ:

```bash
export TAURI_SIGNING_PRIVATE_KEY="$(<.tauri/anion-dl.key)"
export TAURI_SIGNING_PRIVATE_KEY_PASSWORD=""
bun run tauri build --bundles app
```

## Состояние

Э0–Э7, упаковка macOS и синхронизация UI с фронтом `anion` закрыты; Э8
(автообновление) реализован локально и ждёт GitHub secret. Выбор качества и
защита от рекламного манифеста сделаны.
Приложение работает: каталог, поиск, детали, очередь, скачивание в mp4.

ffmpeg 8.1.2 собирается скриптом из официального архива с проверкой SHA-256.
Сборка LGPL без энкодеров; TLS идёт через Secure Transport на macOS, SChannel
на Windows и OpenSSL на Linux. На macOS sidecar весит 2,4–2,6 МБ и зависит
только от системных библиотек. Проверены обе macOS-архитектуры, локальный HLS и
25 секунд живой серии Kodik: H.264 High 1280×720 + AAC-LC, `moov` в начале.

Собственная иконка хранится в `src-tauri/icons/app-icon.png`; остальные размеры
генерируются через `bun run tauri icon src-tauri/icons/app-icon.png`.

DMG собирается для arm64, приложение и ffmpeg подписываются ad-hoc identity
`"-"` с hardened runtime. `codesign --verify --deep --strict` проходит. Это
обеспечивает целостность пакета, но **не заменяет Developer ID и нотарификацию**:
на другой машине macOS всё равно потребует разрешить запуск в Privacy & Security.

## Дорожная карта

**Э6 — минимальная LGPL-сборка ffmpeg. ✅ Сделано.**

Автономный sidecar собран из FFmpeg 8.1.2 с `--disable-everything`, без
`--enable-gpl`, x264/x265 и сторонних dylib.

- Включены демуксеры `hls`/`mpegts`, муксер `mp4`, протоколы
  `file,http,https,tcp,tls,udp,pipe`, BSF `aac_adtstoasc`, парсеры и декодеры
  `aac,h264`. Декодеры нужны только для анализа параметров потока; энкодеров нет.
- `udp` напрямую загрузчик не использует, но OpenSSL TLS в FFmpeg 8.1.2
  ссылается на UDP helpers; без протокола Linux падает на линковке с
  `undefined reference to ff_udp_*`.
- Под MinGW цель Makefile называется `ffmpeg.exe`, а не `ffmpeg`; скрипт
  выбирает цель по платформе.
- [scripts/fetch-ffmpeg.sh](scripts/fetch-ffmpeg.sh) фиксирует версию и SHA-256,
  собирает бинарь и перед установкой отклоняет GPL или несистемные dylib.
- Итоговый размер 2.4 МБ. `otool -L` на sidecar внутри собранного `.app`
  показывает только `/usr/lib` и Frameworks из `/System/Library`.
- Проверены HTTPS через Secure Transport, полный локальный HLS-ремукс и
  25-секундный фрагмент живой серии Kodik из актуального манифеста.

**Упаковка macOS. ✅ Сделано.** Собственная squircle-иконка с прозрачными углами
проверена в размерах 32/128/512 px. `anion-dl_0.1.0_aarch64.dmg` проходит
`hdiutil verify`; внутри есть ссылка на `/Applications`, корректно подписанные
app/sidecar и тот же автономный LGPL ffmpeg без Homebrew-зависимостей.

**Э7 — GitHub Releases. ✅ Настроено.** Тег `app-v<версия>` запускает матрицу
GitHub Actions для macOS ARM/Intel, Windows x64 и Linux x64. Workflow собирает
sidecar на целевой ОС, создаёт недрафтовый Release и загружает DMG, NSIS EXE,
AppImage и DEB со стабильными именами. Версия тега обязана совпадать с
`tauri.conf.json`.

**Э8 — автообновление. ✅ Настроено.**
Подключены updater/process, проверка новой версии при запуске, endpoint
`latest.json`, обязательная подпись update-пакетов и их публикация из workflow.
Приватный ключ добавлен в GitHub Actions secret `TAURI_SIGNING_PRIVATE_KEY`.
Релиз `0.1.2` подтвердил Windows/Linux updater, но macOS отсутствовал в
`latest.json`, потому что матрица собирала только DMG. Начиная с `0.1.3` macOS
собирает `app,dmg`: пользователю остаётся DMG, а updater получает подписанный
`.app.tar.gz`.

Подпись Windows, Developer ID и нотарификация Apple сознательно не делаются:
пользователь получит системное предупреждение при первом запуске.

### Alloha как второй источник — пробовали, отказались

Реализация была доведена до рабочей (живые серии скачивались в 1080p, где у
Kodik потолок 720p), но откачена: цена оказалась несоразмерной выигрышу.
Изменения лежат в `git stash` под именем `alloha-epic` — если тема вернётся,
начинать с нуля не придётся. Что выяснилось по пути:

- **Подпись манифеста живёт около двух минут.** Замерено: запрос на 76-й
  секунде проходит, на 171-й — 403. Счёт идёт от выдачи манифеста, объём и темп
  ни при чём. 23-минутная серия одной сессией ffmpeg не скачивается в принципе.
- **Отсюда покусочная загрузка.** Кусок качается «сколько дадут», процесс
  останавливается по `q` в stdin (не `kill` — иначе не допишется `moov`), очередь
  берёт свежий манифест и продолжает с достигнутой секунды, в конце куски
  склеиваются concat-демуксером. Это переписанный тракт загрузки целиком, плюс
  три дополнительных компонента в сборке ffmpeg (`concat`, `mov`,
  `h264_mp4toannexb`).
- **Между заходами нужна пауза около минуты.** Выкачав сотни мегабайт, Alloha
  перестаёт запускать плеер, и резолв упирается в таймаут. То есть серия качается
  дольше, чем длится, и большую часть времени приложение просто ждёт.
- **Резолв хрупкий на каждом шаге.** UA вебвью Tauri плеер не принимает (нужен
  полный UA Safari, и только для Alloha — Kodik под ним ломается), top-level
  навигацию сервер отдаёт как 404 (страницу приходится монтировать iframe'ом),
  подписанный URL не влезает в канал `document.title` и передаётся частями,
  качество задаётся заранее через `localStorage`, а сам манифест ловится только
  через Resource Timing — мимо `fetch`, `XHR` и `Worker`.

Итог: ради +1080p приложение получает второй тракт загрузки, паузы в минуту
между кусками и пять точек, которые сломаются от любого изменения на стороне
Alloha. Kodik отдаёт серию одним заходом и без единого из этих трюков.

Ожидавшихся Guard-верификации и каскада фолбэк-манифестов не обнаружилось —
прежняя заметка об этом была неверной.
